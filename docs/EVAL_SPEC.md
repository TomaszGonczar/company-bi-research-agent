# OG-154 — v0.1 evaluation specification

Baseline: approved production commit `59e76de`. Establish results before changing identity, retrieval, research, gate, or rendering behavior. This is a deliberately small diagnostic set, not an accuracy benchmark or a COMPLETE-count target.

## Dataset and execution

Use [Pydantic Evals](https://pydantic.dev/docs/ai/evals/) directly: typed `Case`/`Dataset`, one deterministic prediction task and a deterministic evaluator. No LLM judge, model-generated gold, evaluation framework, live requests, credentials, Logfire, or token optimization.

Twelve cases: nine controlled cases and three frozen retained OG-153 real-run replays. Retained replays are offline snapshots, not new live evaluations. Fresh optional live research remains the existing `company-bi batch` command; its changed web content cannot inherit this snapshot gold automatically.

| Controlled case | Main obligations |
| --- | --- |
| `fully_supported` | Core business/scale/financial/news positives; legitimate zero; month-only occurrence must remain null while a genuinely supported event can remain supported. |
| `employee_exact_official` | Exact employee observation with explicit date and same NIP, using a normal abbreviated issuer name rather than requiring the full registry legal-form wording. |
| `employee_conflict` | Two credible, same-date employee statements disagree; no selected quantity or average. |
| `employee_range_stale` | Source-provided 51–200 range and historical observation date; invented exact midpoint/current date must not survive. No new employee-freshness policy. |
| `ellipsis_snippet` | Model-added ellipsis cannot verify an employee claim; a discovery-only business claim cannot become supported. |
| `financial_context_metric` | Operating profit is not total net result; an amount with missing retained currency/context cannot become supported. |
| `invalid_source_id` | Orphan citation fails typed run/gate validation, never publication. |
| `invalid_nip` | Actual checksum/shape validation rejects malformed input before research. |
| `unresolved_nip` | Actual MF response parser consumes a retained subject-null HTTP fixture, not a mocked expected identity. |

Retained replays: Asseco Poland, LPP and ORLEN. Preserve original source snapshots, drafts and diagnostics. Public run JSON may be deliberately promoted into evaluation fixture paths; original ignored `runs/` and `outputs/` must not be staged. Gold for finance/employees must distinguish legal entity from Group/segment. News may describe explicitly labelled related Group/segment developments without pretending they are standalone financial records.

## Gold and file contract

`examples/evals/dataset.json` is the native Pydantic Evals dataset index. Each case has `name`, `inputs` and `metadata`; `expected_output` is not generated by running the gate. Inputs contain `nip` and either `run_file` (relative retained CompanyResearchRun JSON) or `registry_file` (subject-null raw MF JSON). Invalid NIP needs neither. Data files live relative to this index.

Metadata contains:

- `provenance`: `controlled` or `retained_live`; `categories`: explicit labels;
- `expected_outcome`: `published`, `rejected`, `invalid_input`, or `unresolved`;
- `identity`: explicit expected NIP, legal-name value, KRS, REGON and address values; a map of expected nulls represents an invalid/unresolved identity;
- `claims`: manually reviewable fact annotations.

Each claim has:

- `path`: fixed profile fact path, e.g. `business_description`, `employees`, `financials.0`, `recent_developments.1`, `identity.krs`;
- `eligible`: whether retained eligible evidence suffices for the useful gold claim, independent of candidate quality;
- `supported_fields`: approved fields/values/context of a supported observation, or null when no supported observation is defensible. Include `value` and relevant date/metric/period/currency/unit/scope fields. Compare complete event values, so a fabricated optional occurrence date is not hidden by a supported parent state;
- `allowed_states`: contract-correct states (`supported`, `uncertain`, `unknown`, `missing`), not copied from baseline prediction;
- `required_fields`: optional safety constraints, such as null selected employee quantity or null unsupported date;
- `evidence`: source IDs and exact retained text establishing the gold or the reason it is ineligible; `note`: manual explanation;
- `failure_layer` and `failure_category`: evidence-based primary attribution if useful information is lost. Layers: `retrieval`, `extraction`, `gate`, `unavailable`. Do not infer a gate defect solely from its reason string.

Every potentially supported profile fact must have a gold annotation; unannotated supported facts count as unsupported, not silently excluded. Identity coverage is explicitly enumerated so registry facts cannot hide zero researched yield. A rejected case is recorded as rejected, not converted into a fabricated unknown profile.

Gold is reviewed against retained source text before the first baseline run. Freeze the dataset hash with results. Do not revise annotations after observing metrics to erase failures. A correction to a demonstrably mistaken annotation must be separately documented, never silently substituted.

## Separate metrics

Report integer numerators/denominators and percentages only when the denominator is nonzero. `0/0` is unavailable, not 100%.

- Identity correctness: exact retained resolved NIP/legal entity/official identifier preservation, separately from invalid/unresolved outcome handling. This is not a new live registry-coverage claim.
- Supported-claim precision: correctly supported observations / all published supported observations. Show total, registry-only and researched-only precision.
- `unsupported_as_supported`: absolute false-supported count, including unannotated supported facts and context/date/value errors.
- Researched supported-claim recall: eligible gold claims published as supported with approved value/context / all eligible researched gold claims.
- Over-downgrade rate: eligible researched gold claims ending uncertain or unknown / all eligible researched gold claims. Report missing/rejected outcomes separately so omissions cannot disappear from recall.
- Correct uncertain handling and correct unknown handling: correct state plus required safety constraints / annotated uncertainty or missing-information obligations.
- Per-case eligible outcomes: supported, uncertain, unknown, missing; retain actual gate reasons and manually evidenced primary loss attribution.

Do not average case percentages or report a single combined score. Aggregate raw counts. Keep source-availability losses distinct from candidate extraction defects and exact eligible candidate gate rejections. Retain existing searches, reads, model requests, input/output tokens, duration, browser attempts, repairs and unavailable cost; offline replay timings are not original research timings.

## Deliverables and correction policy

`company-bi eval` runs without web/model credentials and writes machine-readable results plus a human-readable run report under an evaluation output directory. Commit the frozen baseline result and `docs/EVAL_RESULTS.md`; preserve baseline if any justified fix follows. Core tests must cover plausible evaluator consumer bugs: zero denominators, weighted aggregation, false-supported context/value mismatch, eligible omissions and safety-state distinctions, not wording or mock echoes.

A production correction is optional, and requires a reproducible general defect, a failing-before regression and a small safety-preserving correction. Low recall alone is not permission for fuzzy matching, snippet promotion, company-specific exceptions, guessed dates/financial context, prompt changes or another model. If no small safe correction is warranted, publish the measured low coverage honestly and leave production behavior unchanged.
